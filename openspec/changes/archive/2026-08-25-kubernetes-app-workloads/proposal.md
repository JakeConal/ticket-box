## Why

The application stack (api, web, postgres, redis, ingress) is the only part of the Kubernetes migration that has not been started: `k8s/argocd/` and `charts/` already cover Jenkins, SonarQube, and Mailpit, but there is no `charts/ticketbox-app`, no `ticketbox` namespace manifests, and no ArgoCD Application for the app itself. Without it, the migration cannot demonstrate the thing that actually matters for a portfolio piece — the ticket-selling app running on Kubernetes with GitOps deploys — and the CI/CD pipeline work in a later change has nothing to deploy to.

## What Changes

- Add a self-authored Helm chart `charts/ticketbox-app` covering: `api` Deployment, `web` Deployment, `postgres` StatefulSet (PVC), `redis` StatefulSet (PVC, `--appendonly yes`), an Ingress (ingress-nginx) routing `/api/*` and `/actuator/*` to `api`, `/*` to `web`, and a ConfigMap for non-sensitive `api`/`web` env vars.
- Define the Kubernetes Secret inventory the chart expects out-of-band (not generated by the chart): `ticketbox-db`, `ticketbox-jwt`, `ticketbox-payments`, `ticketbox-nvidia`, `ticketbox-qr` — mirroring `.env.example`.
- Add an ArgoCD `Application` manifest (`k8s/argocd/ticketbox-app.yaml`) pointing at `charts/ticketbox-app`, deployed into a new `ticketbox` namespace, manual sync (consistent with the existing jenkins/sonarqube/mailpit Applications).
- Move the QR keypair from the bind-mounted `./storage` volume (current compose behavior) to a dedicated secret mount (`ticketbox-qr` at `/app/keys`), keeping a separate PVC for `imports`/`storage` (artist PDFs, VIP CSVs) only.
- `api` and `web` run with `replicas: 1` initially (shared-storage simplicity, matches current compose scale).
- No changes to `docker-compose.yml` — Compose remains the local-dev path; this only adds the Kubernetes path.

## Capabilities

## Impact

- **New files**: `charts/ticketbox-app/**` (Chart.yaml, values.yaml, templates for api/web/postgres/redis/ingress/configmap), `k8s/argocd/ticketbox-app.yaml`.
- **New cluster resources**: `ticketbox` namespace; Deployments (api, web); StatefulSets (postgres, redis) with PVCs; Ingress; ConfigMap; five Secrets created out-of-band (kubectl, not committed).
- **No changes** to `api/`, `ticketbox-web/`, `docker-compose.yml`, or `nginx/` — this proposal packages the existing images/config for Kubernetes, it does not change application code.
- **Depends on**: an ingress-nginx controller and ArgoCD already installed in the target cluster (out of scope here — assumed prerequisite, matches Phase 0 of the prior migration notes).
- **Out of scope**: Jenkins/SonarQube/Mailpit (already have charts/ArgoCD apps), CI pipeline rework (Kaniko builds, image-tag-bump deploy stage) — tracked as a separate future change.
